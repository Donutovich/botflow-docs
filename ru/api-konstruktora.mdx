API конструктора позволяет обращаться к боту из ваших скриптов и сервисов по ключу. Сейчас доступны
два действия: получить данные подписчика и запустить воронку в боте, отправив callback от имени
подписчика.

## Ключ и доступ

Ключи создаются в настройках бота, в разделе «API ключи». Раздел доступен администраторам.

<Steps>
  <Step title="Создайте ключ" icon="key">
    Откройте «Настройки бота» → «API ключи» → «Добавить API ключ». Выберите права, задайте название и
    нажмите «Сгенерировать».
  </Step>
  <Step title="Скопируйте значение" icon="copy">
    Скопируйте ключ и вставьте его в свой запрос. Значение всегда можно посмотреть позже кнопкой копирования
    в списке.
  </Step>
</Steps>

Права ключа выбираются при создании и не могут быть шире ваших собственных: нельзя выдать ключ на
чтение данных подписчиков, если вам эти данные показываются скрытыми, и нельзя выдать ключ на запуск
бота, если у вас нет права запускать воронки в этом боте. От прав ключа зависит, какие запросы он
может выполнять:

| Право | Что разрешает |
|---|---|
| **Чтение информации о подписчиках** | Получать данные подписчика. |
| **Запуск бота** | Запускать воронку в боте, отправляя callback. |

<Note>
  Ключ только для чтения не сработает на запуск воронки. Для запуска нужно право «Запуск бота».
</Note>

Ключ передаётся в заголовке `Authorization`:

```text
Authorization: Bearer ВАШ_КЛЮЧ
```

Базовый адрес всех запросов:

```text
https://botflow.cc/api/v1/bot
```

## Получить подписчика

Возвращает данные подписчика этого бота: имя, username, тег, переменные и дату подписки.

- **Метод и адрес:** `GET /subscribers/{telegram_id}`
- **Право доступа:** «Чтение информации о подписчиках»

| Параметр | Описание |
|---|---|
| `telegram_id` | Telegram ID подписчика, целое число. |

```bash
curl https://botflow.cc/api/v1/bot/subscribers/123456789 \
  -H "Authorization: Bearer ВАШ_КЛЮЧ"
```

Ответ:

```json
{
  "telegram_id": 123456789,
  "first_name": "Ann",
  "last_name": null,
  "username": "ann",
  "tag": "vip",
  "is_blocked": false,
  "subscribed_at": "2026-08-20T10:00:00+00:00",
  "variables": { "plan": "gold" }
}
```

Если подписчика с таким `telegram_id` в боте нет, приходит ответ 404.

## Запустить воронку callback'ом

Отправляет в бот callback от имени подписчика, как будто он нажал inline-кнопку. Так можно запустить
нужную ветку воронки из своего сервиса.

- **Метод и адрес:** `POST /fire-callback`
- **Право доступа:** «Запуск бота»

| Параметр | Описание |
|---|---|
| `telegram_id` | Telegram ID подписчика, целое число. |
| `callback_text` | Значение callback, от 1 до 256 символов. Его ловят стрелки «По нажатию кнопки» и стартовые условия с тем же значением. |

```bash
curl -X POST https://botflow.cc/api/v1/bot/fire-callback \
  -H "Authorization: Bearer ВАШ_КЛЮЧ" \
  -H "Content-Type: application/json" \
  -d '{"telegram_id": 123456789, "callback_text": "start_promo"}'
```

Ответ всегда одинаковый: запрос принят. Если подписчик уже есть в целевом боте, воронка
запустится сразу; если его ещё нет, callback дождётся его появления:

```json
{ "status": "accepted" }
```

### Повторные запросы

Если ваш сервис повторяет запрос при таймауте или обрыве, добавьте заголовок `Idempotency-Key` со своим
уникальным значением на каждую операцию:

```text
Idempotency-Key: promo-2026-09-27-123456789
```

С тем же ключом и тем же телом платформа вернёт сохранённый ответ, а воронка второй раз не запустится.
Тот же ключ с другим телом это уже другая операция, и запрос получит ответ 409. Без заголовка поведение
прежнее: каждый запрос запускает воронку.

<Note>
  Callback не создаёт подписчика. Если подписчика в целевом боте ещё нет, callback ждёт и
  срабатывает, когда тот напишет боту, в течение 14 суток. Что происходит с несовпавшим callback и
  какие переменные доступны в целевом боте, описано в разделе
  [Конструктор, действие «Другой бот»](/ru/constructor). Воронка, запущенная через API, не может
  вызвать callback в другом боте.
</Note>

## Ошибки

При ошибке приходит соответствующий код ответа и тело с пояснением.

| Код | Что означает |
|---|---|
| **401** | Неверный или отключённый ключ, либо сотрудник, создавший ключ, отключён. |
| **403** | У ключа нет нужного права. |
| **404** | Подписчик не найден (для запроса данных подписчика). |
| **409** | Тот же `Idempotency-Key` пришёл с другим телом запроса. |
| **422** | Неверные параметры запроса. |
| **423** | Работа с ботом временно недоступна: проверьте баланс компании или обратитесь в поддержку. |
| **429** | Превышен лимит запросов. |
| **503** | Запрос временно не удалось принять, повторите позже. |
